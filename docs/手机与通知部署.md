# 手机与通知：部署准备，尚未真机验收

本地网页HTTP入口只用于本机。手机不能使用电脑的127.0.0.1。请在可信局域网部署HTTPS反向代理，先选择Android Chrome测试；其他浏览器不得在未测试前宣称兼容。

`deploy/Caddyfile.example` 是待填写的模板，不会自动修改证书、防火墙或发布公网。使用者需选择实际局域网名称/地址和可信证书，然后在 `.env.local` 设置：

```dotenv
COOKIE_SECURE=true
WS_PUBLIC_URL=wss://实际局域网域名/ws/events
ALLOWED_ORIGINS=https://实际局域网域名
```

Java和Flask仍绑定127.0.0.1，通过代理统一入口；不要直接放开8081。不要在手机上绕过证书安全警告，需要先完成合法的证书信任配置。

可选离线推送：

1. 安装 `requirements-notifications.txt`。
2. 运行 `scripts/generate-vapid.py`，把输出的公钥及私钥路径写入 `.env.local`，填写真实的管理员联系邮箱 `VAPID_SUBJECT=mailto:...`。私钥留在本机并限制访问。
3. 确认可以使用浏览器厂商推送服务后，手工设置 `NOTIFICATION_ENABLED=true`，重启Java和Flask。
4. 家属登录手机网页后点击“订阅通知”，由本人同意浏览器权限。界面会报告不支持、拒绝授权或未配置公钥，不能把这些状态写成成功。
5. 用明确标注的模拟事件测试：后台新增通知任务、发送器更新SENT/RETRY/FAILED、手机收到不含老人姓名/照片的提示、点击后仍需身份校验才能读详情。

通知由Java创建、校验订阅用户状态和家属范围，Python仅执行可选发送传输。失败最多尝试5次，每轮间隔约60秒；401/403停止向后台盲目重试。网络结果不确定时可能重复送达，用事件tag帮助合并，不能保证恰好一次。`SENT`表示推送服务接受，不表示手机已经阅读。

通知内容默认只有“有新的监护消息，请登录平台查看”，不含人脸图片和敏感详情。浏览器、系统省电、断网会影响送达；**不能用Web Push替代需要可靠性保障的急救呼叫设施**。

管理员可调用 `GET /api/v1/notifications/jobs` 查看任务结果。取消订阅使用 `DELETE /api/v1/notifications/subscriptions`，会删除当前用户登记的订阅；共享设备换人登录后必须重新确认订阅归属。

依据：[MDN Push API](https://developer.mozilla.org/en-US/docs/Web/API/Push_API)、[pywebpush项目文档](https://github.com/web-push-libs/pywebpush)。
